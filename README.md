# KuntoGether

TV 브라우저를 화면으로, 폰을 컨트롤러로 쓰는 멀티플레이 게임. 접속은 PeerJS, 게임 엔진은 [Kortfinite](https://github.com/Dr1hoon2do/Kortfinite)의 `KuntoGame/`을 가져다 쓴다.

## 저장소 구조 (게임별 폴더)
- `index.html` — 게임 허브 (게임을 고르고 TV 열기 / 방 코드로 폰 접속)
- `party/` — **파티 게임 (미니게임 모음)**. 폰은 컨트롤러 전용. 셸(로비·소개·결과·최종 순위·접속·입력)은 완성, 미니게임은 `party/games/`에 하나씩 추가 (규약: `party/SPEC.md`)

## 파티 (party/)
- `party/tv.html` — TV 호스트. 방 코드가 뜨고 폰이 접속하면 로비 → (게임 소개 → 3·2·1 → 미니게임 → 결과) × 라운드 → 시상대. `?dev`(개발용 게임 표시) `?rounds=3|5|7|10` `?seed=N`. PC 시험은 **Tab**으로 키보드 플레이어 추가 (WASD/방향키, Space·J = A, K·Enter = B)
- `party/pad.html` — 범용 컨트롤러. TV가 보내는 화면 구성(스틱·조준·버튼 최대 4개·모션)대로 그린다. 큰 터치 영역, 버튼 진동, 스틱 고정 방지, 재접속(같은 기기 = 같은 플레이어), PC 키보드·마우스 지원
- **미니게임 추가**: `party/games/내게임.js`에서 `PartyGames.register({ id, name, rule, view, players, duration, controls, create(ctx) })` → `tv.html`에 `<script>` 한 줄. 입력(`ctx.input`), 시드 난수(`ctx.rng`), 끝내기(`ctx.end`), 장면 자동 정리(`ctx.create`/`ctx.scene`)는 `party/SPEC.md`
- **미니게임 목록**: `bomb.js` 폭탄 돌리기(탑뷰, 2~8명, 90초 상한, 엔진 `World2D`) — 스틱 이동 · A 돌진, 폭탄을 든 채 터지면 탈락, 닿으면 폭탄이 넘어감(넘긴 사람 0.6초 면역 / 받은 사람 0.35초 락), 폭발 폭풍으로 주변이 날아감, 터질 때마다 벽이 좁혀짐, 짝수 라운드마다 변수(얼음 바닥 / 폭탄 두 개), 순위 = 탈락 역순(동시 탈락은 공동). 수치는 `window.BombCfg`.
- **탑 오르기** (`climb.js` + `climb_gen.js`, 플랫포머, 2~8명, 90초): 용암이 차오르는 높이 ~2000(약 200m)의 탑을 올라 꼭대기 깃발에 먼저 닿기. 스틱 이동 · A 점프(길게 누르면 높게, 코요테 0.1초·선입력 0.12초) · B 밀치기(앞 46 안의 라이벌을 날려 0.3초 조작 불가, 쿨타임 1.1초). 용암에 닿으면 탈락(그 높이가 기록), 첫 도착자가 나오면 6초 뒤 종료. 순위 = 도착 순서 → 나머지는 도달한 최고 높이(같으면 공동). 발판은 모두 한쪽 통과(아래에서 뛰어 오르고 아래+점프로 내려옴) + 이동(최고 속도 ≤112u/s) · 부서지는(밟고 0.45초 뒤 무너지고 3초 뒤 복구) · 얼음 · 스프링(점프 660) 종류가 아래(쉬움·넓음)→위(좁고 위험)로 섞인다. 탑은 `ClimbGen.generate(rng)`가 시드로 만들고 `ClimbGen.validate`가 "땅에서 모든 발판·깃발에 닿을 수 있나(스프링 없이도 깃발까지)"를 점프 모델(올라갈 높이 ≤52, 가장자리 간격 ≤ 비행 거리의 60%)로 검증한다(순수 JS라 Node에서도 돌려 볼 수 있음). 수치는 `window.ClimbCfg`(용암 속도 등), 개발 중 `?dev`면 `window.__climb`로 게임 객체와 봇(`__climb.bots[id] = (p, game) => ({mx, jump, down, shove})`)을 넣어 볼 수 있다. 월드는 엔진 렌더러(엔진 캔버스)에, 글자·HUD는 오버레이에 그려 큰 화면에서도 가볍다.
- 로비: 각자 A = 준비, 모두 준비하면 4초 뒤 자동 시작(방장 B로 즉시). 방장 스틱으로 게임(무작위/특정)·라운드 수 선택. 점수는 1등 3 / 2등 2 / 3등 1 (게임별 `points`로 변경, 동점은 높은 쪽 점수)
- `dungeon/` — 협동 로그라이크 (원래 만들던 게임, 아래 설명은 전부 이 폴더 기준: `dungeon/tv.html`, `dungeon/pad.html`, `dungeon/assets/`)
- `KuntoGame/`, `kuntogame.js` — 엔진 (모든 게임 공용), `shared/` — 방 코드·TURN (공용), `worker/` — TURN 중계

## 던전 (dungeon/)
- `dungeon/tv.html`은 위 설명의 `tv.html`, `dungeon/pad.html`은 `pad.html`, `dungeon/assets/`는 `assets/`.
- `tv.html` — TV 호스트. 5글자 방 코드를 보여 주고 게임을 돌린다 (`?debug`로 FPS 표시, `?res=540|720|1080`으로 렌더 해상도 고정. 기본은 최대 720p로 그리고 프레임이 느리면 자동으로 낮춤)
- `pad.html` — 폰 컨트롤러. 왼쪽 = 이동, 오른쪽 터치 = 공격(드래그로 방향), 오른쪽 아래 버튼 = 대시
- 충돌/물리: 엔진의 `Physics`(Collider2D·격자 광역탐색·스윕 이동·부채꼴/캡슐 질의) 위에서 돈다. 벽·지형은 고정 콜라이더, 캐릭터는 원 스윕 이동(미끄러짐·터널링 없음), 탄은 이동 구간을 쓸어 판정, 근접은 그려진 부채꼴·찌르기(굵은 선) 그대로 판정. `tv.html?debug`로 충돌 모양을 볼 수 있다
- `KuntoGame/` — 엔진 원본 (문서: `KuntoGame/API.md`). `python3 tools/build_kuntogame.py`로 `kuntogame.js` 하나로 묶으면 `<script src="kuntogame.js">` 한 줄로 쓸 수 있다 (엔진을 고치면 다시 빌드)
- `assets/main.js`, `assets/game/` — 게임 코드. **탑다운 협동 던전**: 8층, 층마다 방이 격자로 이어진다 (아이작 방식). 인원 제한 없음, 기준 2~4인
  - 방 종류: 시작 / 일반(적) / 엘리트(강한 적, 무기 보상) / 보물(패시브·무기) / 상점(골드로 구매) / 보스. **보물방·상점은 5층까지만**, 6층부터는 없다. 8층 보스(마왕)를 잡으면 클리어
  - 인원이 늘면 보물·상점·보상 개수가 늘고, 적은 체력뿐 아니라 **탄 개수·탄 속도·패턴 빈도**가 같이 강해진다
  - `Floor.js` 층 지도 생성 (가끔 큰 방: 이웃한 칸 2~4개를 합친 모양 — 2칸·L자 3칸·2×2 4칸, 액티브 충전 2) · `Obstacle.js` 지형지물(구덩이·제단·기계 포함, 기둥·바위·상자·폭발 통, 일부는 부서짐, 플레이어보다 충분히 큼) · `Weapons.js` 근접 11종 + 원거리 9종 × 등급 5단계 (무기는 사거리·범위·모양·데미지·공속·공격 중 이동 감속만) · `Items.js` 패시브 156종 + 액티브 32종(등급 없음, 가격 15G 고정)(충전형·쿨타임형)
  - **타일맵 기반 방**(`assets/game/tiles/`): 방 한 칸 = **16×9 타일**(타일 25 → 400×225, 아이작과 같은 격자). **16×9 칸 전체가 플레이 영역**(400×225, 예전엔 테두리 한 칸을 빼서 14×7 = 350×175였다 → 넓이 +47%)이고, 바깥 벽은 칸 바깥에 반 타일(12) 두께의 띠로 그려진다. 문 틈은 위아래 2칸·양옆 3칸 위치의 띠에 뚫린다. 방 구성 데이터는 안쪽 14×7 틀로 만들고 생성기가 마지막에 가장자리 한 줄을 바닥으로 바꾼다. 큰 방은 칸을 이은 격자(2칸 32×9 / 16×18, L자, 2×2 32×18)이고 L자의 빈 칸은 마스크로 막힌다. 타일 종류: 바닥·벽·기둥·바위·상자·폭발 통·**구덩이**(걸어서는 못 지나가지만 탄은 지나감)·제단·기계·가시·받침대·금 간 벽. 모든 지형은 한 타일(25) 이상이고 격자에 정렬된다.
    - **파일**: `Registry.js` 콘텐츠 레지스트리 + **`SPEC.md` 콘텐츠 규약** · `TileMap.js` 타일맵(합치기·flood fill·정적 타일 그리기) · `TileGen.js` 생성기 · `ArchetypesNormal/Boss/Special.js`(A: 방의 큰 구성) · `Stamps.js`(B: 작은 조각) · (콘텐츠가 없거나 모두 실패하면 테두리·문만 있는 빈 방 폴백).
    - **충돌**: 이웃한 벽·구덩이는 큰 직사각형 콜라이더 하나로 합친다(greedy merge — 벽 타일 11만 개 → 콜라이더 2.5만 개). 부서지는 상자·통·바위는 타일마다 하나이고, 부서지면 타일맵도 바닥이 된다(방을 나갔다 와도 유지). 벽·기둥·구덩이·받침대는 방 바닥 캔버스에 **한 번만 구워서** 그려서(방이 바뀔 때만) 프레임 비용이 늘지 않는다.
    - **생성 순서**(`TileGen.js`): ① 시드 난수로 좌우/상하 뒤집기 → 뒤집힌 틀의 `ctx`(문·통로·예약 구역도 같이 뒤집힘)로 `archetype.build(ctx)` ② 받은 문자 격자를 되돌려 타일맵에 쓰고 **테두리 벽·문 틈·금 간 벽을 생성기가 그림**, 예약 구역(문 앞·칸 사이 통로·시작·보스 4×4 자리)은 비움 ③ archetype의 `stampSets`에서 `stampCount`만큼 **스탬프**를 놓음(좌우 반전 무작위, 앵커 규칙, 둘레 한 타일은 비움, **같은 스탬프를 거울 쌍으로 놓지 않음**, 놓을 때마다 흐름 검사해서 막히면 되돌림) ④ **밀도 보정**: 전투 방의 안쪽 열린 비율이 목표(방마다 0.70~0.83)보다 높으면 스탬프를 더 놓는다(평균 0.82). **비대칭 섞기**: 작은 지형(상자·바위·통·기둥)을 몇 개 지우고 몇 개 새로 놓고, 아직 거울 대칭에 가까우면(0.72↑) 거울 자리가 빈 곳에 더 놓음 — 전투 방만(제단·가시·상점 같은 설계된 특수 방은 그대로) ⑤ **검증**.
    - **검증**: 한 문에서 출발해 **모든 문·칸 사이 통로·보스 자리·보상 자리에 닿는지**(부서지는 상자·통도 막힌 것), 보스 방은 덩치(2×2 타일)가 지나갈 수 있는지, 닿을 수 없는 구멍은 벽으로 메우고(12% 넘으면 다시), 열린 칸 비율(전투 방 45% / 보스 55%). 실패하면 다른 시드로 최대 14번, 그래도 안 되면 안전한 빈 방(폴백). 적은 도달 가능한 타일 가운데에만 나온다(상자 사이에 갇힌 자리 포함). 보스 등장 자리는 **들어온 문 반대쪽** 4×4.
    - **시드**: 런 시드 → 층 시드(`hash2(런시드, 층)`) → 방 시드(`room.seed`). 같은 시드면 같은 층 구성·같은 방 배치(적·아이템 드랍은 시드와 무관). 주소에 `tv.html?seed=123`(숫자 또는 아무 글자)로 고정할 수 있고 화면에는 표시하지 않는다.
    - 콘텐츠가 알려준 `slots`(받침대·보상·더미 자리)는 월드 좌표로 바뀌어 `room.layout.slotsW`에 담기고 `Game._layout`·가시방/비밀방/매복방 보상이 쓴다.
  - **비밀방**(2~7층, 층마다 25% 확률로 최대 1개): 일반·엘리트 방의 벽 너머 막다른 방. 처음엔 지도에도 문에도 없고, 호스트 방 한쪽 벽(문 자리)이 **금 간 벽 타일**(`k`, 생성기가 지정)이다. **폭발**(폭탄·폭발 통·폭발 아이템)이 가까이서 터지면 한 번에, 근접·원거리·광선 **공격은 누적 피해 12**로 벽이 깨져 문이 열린다(지도에 방이 나타남). 안에는 적이 없고 보상(아이템 1개 또는 코인·하트·열쇠 더미). 나침반 아이템이 있으면 지도에 자리만 점선으로 보인다. 그래프 밖에 붙은 막다른 방이라 보스까지 가는 길에는 영향이 없다.
  - **특수 방**(`Specials.js`, 정의는 `Floor.js`의 `SPECIAL_ROOMS`): 막다른 방에 가끔 나온다. 층마다 종류별 최대 1개·한 층 최대 2개, 층 범위 안에서만(보물·상점은 여전히 5층까지).
    - **가시방**(2~8층): 들어갈 때 모두 체력 1(마지막 1은 남김). 바닥 가시 판이 주기적으로(안전 1.5초 → 준비 0.45초 → 솟음 0.85초) 솟고, 판 모양이 곧 피해 범위다. 건너편에 아이템(+코인).
    - **희생방**(2~7층): 제단에 닿으면 체력 1을 바친다(**체력 1이어도 바칠 수 있고, 그러면 죽는다** — 보스 방 클리어 때 부활). 바친 횟수별 보상이 **고정**: 1 코인2 · 2 열쇠 · 3 하트 · 4 코인4 · 5 패시브 · 6 무기 · 7 액티브 · 8 대박(열쇠2+하트+상자), 8번 뒤엔 끝. 제단 위 점이 바친 횟수.
    - **도박방**(2~7층): 기계 앞에서 공격 = 3G로 돌리기(꽝 40%·코인 3/5/10·열쇠·하트·폭발·아이템, 평균 이득 < 3G). 폭발이 나오거나 4%로 고장.
    - **악마 상점**(보스 방 옆방, 지도에는 없음): 보스 방을 클리어할 때 **보스전에서 맞은 횟수**에 따라 열린다 — 확률 = 0.5^맞은 횟수(안 맞으면 100%, 1번 50%, 2번 25%, 3번 12.5%…, `devilChance`). 열리면 보스 방에 붉은 포탈이 생기고(계단은 그대로), 포탈에 서면 들어가고 문으로 나오면 포탈 옆으로 돌아온다. 골드 대신 **최대 체력**으로 산다(하트 그림이 값, 그 판 동안 영구히 줄어든다 — 주사위로 아이템을 다시 뽑아도 유지): 패시브·무기 1하트, 액티브 2하트, 최대 체력 1 → 8G, 최대 체력 1 → 열쇠 3개. 최대 체력이 2 아래로 내려가는 거래는 못 한다(사다가 죽지 않음). 품목 수는 인원수에 비례. 8층(마지막)에서는 안 열린다.
    - **매복방**(3~7층): 적이 3번에 걸쳐 몰려온다 → 인원수만큼 아이템. **서재**(3~8층): 열쇠 1개로 들어가는 방, 인원수+2개 중 인원수만큼만 고를 수 있다.
  - **열쇠 문**: 2층부터 보물방·상점·서재 문이 잠겨 있다(1층은 그냥 입장). 열쇠(`game.keys`, 팀 공유) 1개로 한 번 열면 계속 열려 있고, 열쇠가 없으면 문이 닫힌 채 `block` 소리만 난다(문에 자물쇠, 미니맵에 노란 점). 시작 방에 가까운 일반 방 2개는 클리어하면 열쇠를 확정으로 줘서(`room.keyDrop`) 층당 최소 2개(2인 평균 약 3.8개)가 보장된다. 순간이동 액티브는 잠긴 방으로 못 간다.
  - 카메라는 모든 방에서 같은 배율(한 칸 + 바깥 벽 띠가 한 화면에 들어오게 가로 432×세로 243 — 예전 400×225보다 8% 멀리)이고, 플레이어들을 따라다닌다(큰 방에서 너무 멀리 나간 플레이어는 화면 밖). 축소해서 맵 전체를 보여주지 않는다
  - **골드는 팀 공유**이고, 골드 관련 아이템(획득량·코인 드랍·방 클리어 보너스·상점 할인·나침반)은 파티 전체에 합산 적용된다
  - 근접 공격은 기본으로 범위 안의 적 탄을 지운다. 반사 거울(근접 전용)이 있으면 되받아친다. 원거리 무기는 탄을 못 지운다
  - 난이도: 쉬움/보통/어려움 — 폰 접속 화면(또는 TV 키보드 1/2/3)에서 선택, 첫 문으로 나가면 고정. 시작 체력(8/6/5)·적 체력·공격 빈도·탄 수·보스 강화가 달라짐. `DIFFICULTY`(Enemy.js)에서 조절
  - **경제(아이작식)**: 적은 골드를 떨어뜨리지 않는다. 방을 클리어하면 보상이 방 안에 떨어지고 **닿으면 획득**한다 — 코인(1 구리 / 3 은 / 5 금 / 10 파랑; 3·5·10은 드묾), 열쇠(팀 공유, `🔑n`), 하트, 꾸러미(터지면 코인·열쇠·하트가 흩어짐), 상자(열쇠 1개로 열림: 코인 2~3 + 하트/열쇠/드물게 아이템). 확률은 인원수(+12%/명)·큰 방(×1.5)에 따라 조금 늘고 층이 오를수록 조금 줄어든다 (`Game.js`의 `ECON`). 층당 코인 수입은 2~4인 기준 1층 약 17~20G, 3층 약 20~22G, 5층 약 26~29G(상자·꾸러미 포함, 상자는 열쇠 소모). 가격: 아이템 15G 고정G, 무기 10/15/20/27/36G, 하트 4G
  - 보상: 보물방·보스방은 인당 아이템(가끔 액티브) 1 + 무기 1, 상점은 (1~3)+인원×2개 품목(하트 4G는 인원수만큼 구매 가능). 획득·구매는 공격(터치)으로
  - 폰: 왼쪽 이동, 오른쪽 터치 공격, 오른쪽 아래 대시, 그 위 액티브 버튼 (키보드 테스트: E 또는 I)
  - 폰은 기기 ID를 저장해 두고, 끊겼다 같은 폰으로 다시 접속하면 같은 캐릭터(아이템·액티브·체력)로 이어진다. 닉네임은 폰 컨트롤러에서 입력. 죽은 플레이어는 보스방을 클리어하면 부활
  - **아이템 시스템** (`Items.js`, 맨 위 주석에 형식·훅 목록): 패시브 156종 · 액티브 33종 (등급 없음, 가격 15G 고정). 무기는 그대로 두고 4가지 **형태**(휘두르기·찌르기·투사체·레이저, `Weapons.js`의 `form`)로 분류해서, 아이템이 형태를 바꾸거나(`conv`, 우선순위 `prio`: 높은 쪽 → 같으면 나중에 얻은 쪽, 변환은 한 번만) 형태별 추가 공격(검기·바늘·광선·갈라지는 레이저)을 붙인다. 검기·바늘은 내 탄이라 튕김·유도·분열·관통·부메랑·상태이상이 근접에도 적용된다
    - 아이템 한 줄 정의: `P(id, 우선순위, 아이콘, 이름, 설명, [태그], { s: 스탯, hp, conv, on: 훅, fam: 동료, cos: 꾸미기, init })`. 스탯 변환형(한쪽을 주고 한쪽을 얻음) · 특색 효과 · 유틸(지도·보호막·여분 대시·열쇠·상자 운) · 협동(오라·연결의 실·나눔 하트·희생의 서약·릴레이 배턴) · 동료 5종. 엉뚱한 소재의 아이템(빨간 두건·오리 호루라기·방귀 쿠션·비누 …)도 모두 실제 효과가 있다(모자는 모양일 뿐). **줍기는 몸이 닿아야 하고 끌어당기는 자석 효과는 없다**
    - **분신·조종·반복 공격** (`ItemFx.js`): 분신 인형(앞)·거울 분신(뒤, 반대 방향)·그림자 쌍둥이(1초 전 위치)가 내 공격을 자기 위치에서 따라한다 · 릴레이 배턴(아군 위치에서 따라함) · 잔향의 종(3번째 공격마다 0.5초 뒤 같은 자리에서 한 번 더) · 조종 구슬/유령 검(루도비코: 공격 스틱을 끄는 방향·세기로 날아가 닿는 적을 벰) · 회전 칼날 · 휘는 탄(이동 스틱으로 꺾임) · 충전 장갑 · 불씨/반짝이/방귀/비누 장판 · 포탑 상자 · 폭탄 시체(양철 방울) 등
    - **액티브 33종**: 충전형은 아이작식 — 게이지가 가득 차야 쓸 수 있고 쓰면 전부 소모. 충전 방식이 5가지 — `charge` 방 클리어(큰 방 2) · `cooldown` 쿨타임 · `kill` N마리 처치 · `dmg` 피해 N 누적 · `floor` 층마다 N회. 주사위(작은 주사위=가장 가까운 바닥 아이템 하나 다시 뽑기, 붉은 주사위=가진 패시브 전부 무작위로, 푸른 주사위=이 방 바닥 픽업을 무작위 픽업으로), 점쟁이 카드(바닥 아이템 다시 뽑기), 되감기 시계(클리어한 방 한 번 더·방마다 1회·보상도 다시), 텔레포트 두루마리/귀환석, 분신 소환, 포탑 설치, 부활의 종, 수혈, 연금술 가루(동전→열쇠→하트), 환전소, 저주 인형, 복수의 칼날, 분노 게이지, 룰렛 …
    - 상태이상 6종(화상·둔화·빙결·중독·감전·출혈)과 반응(화상×빙결=증기, 화상×중독=독불, 감전×빙결=초전도), 태그 세트 7개(같은 태그 3개 모으면 보너스), 짝 시너지 6개
    - 이벤트 훅: `game.fire(이름, 일으킨 플레이어, a, b)` — `swing hit kill damaged dash shieldBreak active roomEnter roomClear coinPickup keyPickup heartPickup chestOpen`
  - `Sfx.js` 아주 간단한 효과음(WebAudio 합성, 첫 키 입력 후 켜짐, M 음소거)
  - `Enemy.js` 적 정의 표(`ENEMY_DEFS`)와 스케일(`BALANCE`, `calcScale`). 새 적은 표에 한 항목 + `ENEMY_POOL`에 등장 층·가중치. 일반 적 28종(대부분 행동 모드 2개 이상을 번갈아 씀: 쫓기·옆으로 돌기·도망·배회·깡총·튕겨 다니기 등) + 보스 13종 + 마왕(8층 고정). 층마다 비슷한 난이도의 보스 2종 풀(`BOSS_POOLS`)에서 무작위로 나옴(1층 보통 = 슬라임왕 기준으로 맞춤). 공격 패턴(shoot·burst·ring·ringgap·spiral·orbs·rain·wall·bombard·cross·charge·slam·leap·teleport·summon·heal)과 탄 옵션(bounce·homing·wave)은 매개변수로 조절. 보스 무적 해제 방식은 보스마다 다름(수호자·도는 구체·수정·벽에 들이받게 하기·시전 중 무적, 없는 보스도 있음) — 파일 위쪽 주석 참고
  - `Hero.js` 플레이어, `Pickup.js` 바닥 아이템·구매(가까이 가면 정보, 공격하면 획득·구매), `Game.js` 진행·HUD·접속
